Épisode 6 Construire les compétences

  • Niveau Grand débutant
  • Langages HTML5 · CSS3 · JavaScript
  • Durée indicative 30 à 45 min de vidéo · 2 h 30 en séance
  • Fichier modifié index.html (config.js inchangé)

Objectif de l'épisode

Écrire « je maîtrise Windows Server » sur un CV, tout le monde le fait. Le montrer avec une jauge qui se remplit sous les yeux du recruteur, c'est bien plus marquant. Vous allez construire la section Stack technique : 15 compétences en trois colonnes qui apparaissent en cascade, des barres qui se remplissent quand elles entrent dans l'écran, et un nuage de badges pour les outils étudiés.

Partie 2

Objectif pédagogique

À la fin de cet épisode, vous serez capable de construire des composants répétés (des cartes) à partir d'un seul modèle, de stocker une donnée dans le HTML pour la lire en JavaScript, et d'animer une jauge avec une simple transition CSS.

Ce que vous saurez faire

  • Écrire un composant (la carte de compétence) une fois en CSS, et le réutiliser quinze fois en HTML.
  • Disposer trois colonnes égales avec la grille Bootstrap (col-lg-4) et empiler des cartes avec d-flex flex-column gap-3.
  • Ranger des étiquettes en « nuage » avec flex-wrap.
  • Ajouter un décor sans HTML avec le pseudo-élément ::after.
  • Stocker une valeur dans un attribut data-* et la lire en JavaScript avec dataset.
  • Réutiliser IntersectionObserver pour un deuxième usage, et créer un effet de cascade avec transition-delay.

Les nouveaux mots de cet épisode

Les mots des épisodes précédents sont dans les listes des épisodes 1, 2, 3, 4 et 5.

Stack technique
L'ensemble des technologies qu'une personne maîtrise.
Composant
Un morceau d'interface réutilisable : une même structure HTML et une même classe CSS, répétées autant de fois que nécessaire.
Attribut data-*
Un attribut que l'on invente soi-même (data-width="80") pour stocker une donnée dans le HTML.
dataset
En JavaScript, l'objet qui donne accès aux attributs data-* : element.dataset.width lit data-width.
Pseudo-élément ::after
Un élément décoratif que le CSS ajoute à la fin d'un élément, sans l'écrire dans le HTML.
transition-delay
Le temps d'attente avant le début d'une transition.
flex-wrap
Autorise les éléments d'une boîte flex à passer à la ligne quand la place manque.
inline-flex
Une boîte flex qui se place dans le texte comme un mot, au lieu de prendre toute la largeur.
Rôle progressbar
Annonce aux lecteurs d'écran une barre de progression ; sa valeur est donnée par aria-valuenow, entre aria-valuemin et aria-valuemax.
Rôle region
Annonce une zone importante de la page, que les lecteurs d'écran peuvent lister pour naviguer.
fab / fas
Deux familles d'icônes Font Awesome : fab pour les marques (Windows, Linux, Docker), fas pour les icônes pleines.

🧩 Le trajet d'une valeur, du HTML à l'écran

<div class="skill-bar" data-width="80"></div>
e.target.style.width = e.target.dataset.width + '%';
width: 0%; transition: width 1.2s cubic-bezier(.4,0,.2,1);

Le HTML garde la donnée (data-width="80"). Le JavaScript la lit (dataset.width → « 80 ») et écrit width: 80% sur la barre. Le CSS transforme ce changement brutal en remplissage progressif, grâce à la transition. Chacun son rôle.

Ligne 828 Colonne 2 : Réseaux, avec un retard 
          <div class="col-lg-4 reveal" style="transition-delay:.12s">
Ce que fait cette ligne

Même colonne, mais un style en ligne retarde son apparition de 0,12 seconde.

Pourquoi elle est nécessaire

C'est l'effet « en cascade » : la colonne 1 apparaît, puis la 2 (0,12 s après), puis la 3 (0,24 s après). transition-delay retarde le début de la transition de .reveal.

Si on la supprimait

Les trois colonnes apparaîtraient en même temps.

Où trouver l'information
  • MDN — La propriété transition-delay
  • MDN — L'attribut style
Pour retenir

Un petit retard par colonne = une cascade.

Erreur 1 Les barres restent vides

Symptôme
Les rails sont là, mais aucune barre colorée, même après défilement.
Cause
Le module 5 manque, une erreur JavaScript l'empêche de s'exécuter, ou l'attribut est mal écrit (data-witdh, data_width).
Solution
Ajoutez les lignes 947 à 959, lisez la Console, comparez l'attribut avec la ligne 807.
Vérification
Onglet Éléments : chaque .skill-bar porte style="width: 80%;" (ou sa valeur).

Erreur 2 Les barres sont pleines tout de suite, sans animation

Symptôme
Les barres ont leur taille finale dès l'arrivée, sans se remplir.
Cause
La ligne 523 manque ou est incomplète : sans width: 0%, la barre n'a pas de point de départ ; sans transition, le changement est instantané.
Solution
Recopiez la ligne 523.
Vérification
Actualisez avec F5, puis descendez : les barres se remplissent en un peu plus d'une seconde.

Erreur 3 Rien ne s'affiche sous le nom

Symptôme
Ni rail, ni barre.
Cause

Solution
Ajoutez la ligne 519.

Un rail de 5 pixels apparaît sous chaque nom.

Partie 14 · facultatif

Défi pour aller plus loin : des barres lisibles par tous

Sur une copie de votre fichier, corrigez les deux défauts d'accessibilité des barres : 1) chaque progressbar doit avoir un nom accessible ; 2) en thème clair, le rail doit rester visible. Vérifiez le premier point dans les outils de développement (F12 › onglet Éléments › panneau Accessibilité).

1. Le nom accessible. MDN l'indique : un progressbar doit avoir un aria-label ou un aria-labelledby. Le nom est sur la carte, pas sur la barre. Il suffit de l'ajouter, par exemple :

                <div class="skill-bar-bg" role="progressbar" aria-label="Windows Server" aria-valuenow="80" aria-valuemin="0" aria-valuemax="100">

2. Le rail. Remplacez la couleur fixe par une variable qui change avec le thème, par exemple la couleur des bordures :

    .skill-bar-bg { height: 5px; background: var(--clr-border); border-radius: 10px; overflow: hidden; }

Le panneau Accessibilité affiche alors un nom pour chaque barre, et le rail reste visible en thème clair. C'est la même logique que tout le thème : une couleur écrite en dur ne suit pas le thème.

Gardez votre fichier principal identique au code de la série.
